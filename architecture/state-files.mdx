The `.gsd/` directory in your project root is the **source of truth** for all GSD state.

## Directory Structure

```
.gsd/
  PROJECT.md            Living doc — what the project is right now
  DECISIONS.md          Append-only register of architectural decisions
  QUEUE.md              Append-only log of queued milestones
  STATE.md              Quick-glance dashboard — always read first
  REQUIREMENTS.md       User requirements (optional)
  preferences.md        Project-specific preferences (optional)
  milestones/
    M001/
      M001-CONTEXT.md      User decisions from discuss phase
      M001-RESEARCH.md     Codebase and ecosystem research
      M001-ROADMAP.md      Milestone plan with slice checkboxes
      M001-SUMMARY.md      Milestone rollup (updated as slices complete)
      slices/
        S01/
          S01-CONTEXT.md     Slice-level user decisions (optional)
          S01-RESEARCH.md    Slice-level research (optional)
          S01-PLAN.md        Task decomposition for this slice
          S01-SUMMARY.md     Slice summary (written on completion)
          S01-UAT.md         Human test script (written on completion)
          S01-CONTINUE.md    Resume point if interrupted (ephemeral)
          tasks/
            T01-PLAN.md      Individual task plan
            T01-SUMMARY.md   Task summary with frontmatter
```

Location: `src/resources/extensions/gsd/prompts/system.md:63-85`

## Naming Convention

**Directories** use bare IDs:
- Milestone dirs: `M001/`, `M002/`, ...
- Slice dirs: `S01/`, `S02/`, ...

**Files** use `ID-SUFFIX` format:
- Milestone files: `M001-CONTEXT.md`, `M001-ROADMAP.md`, `M001-RESEARCH.md`
- Slice files: `S01-PLAN.md`, `S01-RESEARCH.md`, `S01-SUMMARY.md`, `S01-UAT.md`
- Task files: `T01-PLAN.md`, `T01-SUMMARY.md`

Titles live **inside** file content (headings, frontmatter), not in file or directory names.

Legacy descriptor-suffixed names (e.g. `M001-FLIGHT-SIMULATOR/`, `T03-INSTALL-PACKAGES-PLAN.md`) are still resolved via prefix matching for backward compatibility.

Location: `src/resources/extensions/gsd/paths.ts:1-309`

## Root-Level Files

### PROJECT.md

**Living document** describing what the project is **right now**. Updated at slice completion when stale.

Format:
```markdown
# Project Name

## Overview
One paragraph describing the current state of the project.

## Current Capabilities
- Feature 1
- Feature 2

## Stack
- Runtime: Node.js 20
- Framework: Express
- Database: PostgreSQL
```

**Rules:**
- Current state only (not historical)
- Updated when slice completion reveals drift
- Read by agents during research and planning

### DECISIONS.md

**Append-only register** of architectural and pattern decisions. Never edited — only appended to.

Format:
```markdown
# Architectural Decisions

## 2024-03-13: Authentication Strategy

Decision: Use JWT tokens with short expiry (15min access, 7d refresh).

Rationale:
- Stateless auth scales horizontally
- Short access tokens limit blast radius
- Refresh tokens stored in httpOnly cookies

Alternatives considered:
- Session-based auth (doesn't scale)
- Long-lived tokens (security risk)

---

## 2024-03-14: Error Handling Pattern

Decision: Structured errors with codes and context.

...
```

**Rules:**
- Append-only — never edit prior entries
- Include date, decision, rationale, alternatives
- Read during planning and research
- Append during execution when meaningful decisions are made

Format:

### M###-ROADMAP.md

**Milestone plan** with slice checkboxes, risk levels, dependencies, and boundary map.

Format:
```markdown
# M001: Payment Integrations

**Vision:** Add Stripe payment processing for one-time purchases and subscriptions.

**Success Criteria:**
- Users can purchase products with credit card
- Subscriptions auto-renew monthly
- Failed payments trigger notifications
- Admin dashboard shows payment history

---

## Slices

- [ ] **S01: Payment data model** `risk:low` `depends:[]`
  > After this: database schema and types exist for payments/subscriptions.

- [ ] **S02: Stripe webhook handling** `risk:medium` `depends:[S01]`
  > After this: webhook endpoint receives and verifies Stripe events.

- [x] **S03: One-time purchase flow** `risk:low` `depends:[S01,S02]`
  > After this: user can buy a product with Stripe Checkout.

---

## Boundary Map

### S01 → S02, S03
Produces:
  types.ts → Payment, Subscription, PaymentStatus (interfaces)
  db.ts    → createPayment(), getPayment(), updatePaymentStatus()

Consumes: nothing (leaf node)

### S02 → S03
Produces:
  webhooks/stripe.ts → POST handler, verifyWebhook(), handleEvent()

Consumes from S01:
  db.ts → updatePaymentStatus()
```

**Rules:**
- Checkboxes track completion: `- [ ]` = pending, `- [x]` = done
- Risk levels: `low`, `medium`, `high`
- Dependencies: `depends:[S01,S02]` lists slice IDs this slice requires
- Boundary map is **required** — shows what each slice produces/consumes
- Slices are ordered by risk (low risk first)
- Reassessed after each slice completes

Location: `src/resources/extensions/gsd/files.ts:1-300` (parser)

### M###-SUMMARY.md

**Milestone rollup** updated as slices complete. Compresses prior work into a readable overview.

Format:
```markdown
# M001: Payment Integrations — Summary

## Completed Work

### S01: Payment data model
- Created `payments` and `subscriptions` tables
- Added TypeScript interfaces in `src/types/payment.ts`
- Implemented CRUD functions in `src/lib/db/payments.ts`

### S02: Stripe webhook handling
- Webhook endpoint at `/api/webhooks/stripe`
- Signature verification using Stripe SDK
- Event handlers for `payment_intent.*` and `invoice.*`

## Key Decisions
- Store webhook events in `webhook_events` table for debugging
- Use database transactions for idempotent event handling
- Return 200 immediately, process events async

## Outstanding Work
- S03: One-time purchase flow
- S04: Subscription management UI
```

**Rules:**
- Updated when each slice completes
- Read at the start of new slices for context
- Compresses detail — full detail lives in slice summaries
